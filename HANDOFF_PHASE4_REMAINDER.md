# Handoff: Phase 4's remaining slices (`InstrumentManager`, `Synth::render`)

Phase 4 is the only phase left open. Six of its sixteen functions are ported and fixture-verified;
what follows is what a resuming session needs, measured rather than assumed.

## What is left

1. **`Synth::render`** (0xf7ad4, 11 KB) - the last ported function of the phase. Its 52 calls are:
   `interpolateParameters`, `Lfo::render` x5, `InstrumentManager::render` x2, `vibrato` x2,
   `handleOverload`, `trackFilterProcess` x5, `trackFilterDcBlock` x6, `FxManager::render` x4,
   `Sequencer::getBPM` x4, `getActiveTrack` x2, `getInputSelector`, `getModuleSends`,
   `PlugManager::getPlugFlags` x2, `get_time_monotonic` x2, `masterCompressor`, `bounceAudio`,
   `memset`, and the object's own mutex.
2. **Its remaining prerequisites**, all small and each still unported:
   * `Sequencer::getActiveTrack` (0xea954): `*(u32*)(this + 0x30)`, and the synthesised P4 thunks are
     what the library actually exports.
   * `Sequencer::getInputSelector` (0xeb894): 0 when the byte at `+0x61` is set unless the bool
     argument is true and `*g_previewExtInput` is set, in which case the byte at `+0x346a34`;
     otherwise `*(u32*)(this + 0x54)`.
   * `Sequencer::getModuleSends` (0xee3e8): `&DAT_0126b63c` when the byte at `+0x61` is set, else
     `*(u64*)(this + *(i32*)(this+0x44)*0x10 + 0x698) + 0x4b82` - a pointer *stored* in the sequencer,
     so the port needs a way to resolve it.
   * `PlugManager::getPlugFlags` (0xd6ed4): a binary search over the plug map for the id, returning
     the byte at `+0x7a8` of the found plug's record, or 0.
   * `FxManager::render` (0x13cde4): 76 bytes. For `track >= 8` it indexes a 0xf0-byte slot at
     `(track - 8) * 0xf0`; when the active word at `+0xec` is non-zero *and* the function pointer at
     `+0x08` is set, it calls that pointer with
     `(params, *(u32*)(slot + 0xe8), slot + 0x20, a, b, gain)`. With no FX track loaded the whole call
     is a no-op, which is the v1 case.
3. **Wiring**: delete the interim host in `crates/opz-core/src/engine.rs` and point `Engine` at the
   ported chain, then the realtime-safety pass.
4. **Phase 5**: the fidelity pass, `PORT_METHOD.md` updates, and the repeatable-pipeline check.

## `Synth::render`: the port plan the decompilation supports

The Ghidra C (`analyzeHeadless /tmp/ghidra-p4 p4 -process libSnakePlugin.so -noanalysis`, filter
`Synth::render`) is 2 350 lines and usable once the register noise is skipped. Its shape:

1. **Setup** (C lines 1260-1700): `memset` a 0x400-byte scratch at `this + 0x288`, zero a 0x200-byte
   scratch at `this + 0x688`, then read the plug flags (`PlugManager::getPlugFlags` twice), the module
   sends, the active track, the input selector, the BPM four times, and `get_time_monotonic` twice.
2. **The track loop** (`do { } while (track != 8)`, C lines 1700-2070): for every track 0..7
   * track 6 is the FX/master slot: the parameter blocks at `+0x5c78`..`+0x5c90`, `+0x60f8`.. and
     `+0x5c98`.. are copied into the scratch and two scratch words are set to `0x3fffffff`;
   * otherwise two `Lfo::render` calls: layer 1 at `this + track*0x2c + 0x4ee4` with the block at
     `+0x5f48` and out `this + 0x15a0`, then layer 0 at `+0x4d00` with the block at `+0x5ac8` and out
     `this + 0x1554` (both LFOs take `this + track*4 + 0x6ca4` as an input);
   * two `InstrumentManager::vibrato` calls, on `clamp(this+0x15a0's first word + 0xc0000001) << 1`
     and on `clamp(this+0x1554's first word * 2 - 0x7ffffffe)`;
   * zero the 0x200-byte mix buffer at `this + 0xf08`, then `InstrumentManager::render(track, 0, mix,
     this + 0x1554, &counter)` and the same for layer 1 with `this + 0x15a0`;
   * a per-track halfword counter at `this + track*2 + 0x6aac` and a per-track value at
     `this + track*4 + 0x5108`, and the mix-down into the accumulation buffers at 0x1227a20/0x1227e20
     (four track groups of 0x200 bytes) plus the scratch at 0x1228020/0x12284a0, with the layer-0/1
     modulation blocks at 0x1228cec and 0x1228d38 handed to the voices as their parameter block;
   * the four `FxManager::render` calls, five `trackFilterProcess` and six `trackFilterDcBlock`.
3. **The master tail** (C lines 2070-3610): `bounceAudio`, the four `Sequencer::getBPM` reads, the two
   `masterCompressor`-style blends over the mix buffers at `this + 0xee8`/`0xf08`/`0x1108`, the VU
   words, and the writes into the four output buffers the caller passed.

The scratch the function touches is **not** inside the object: the mix buffers and the modulation
blocks are separate `.bss` objects addressed absolutely - 0x1227a20 (0x400, `memset`), 0x1227e20,
0x1228020, 0x12284a0, 0x12286a0, 0x12288a0, 0x1228aa0 (`inputBuffer`), 0x1228cec and 0x1228d38 - so
the port owns one buffer spanning 0x1227a00..0x1228e00 (0x1400 bytes, 1 280 words) and indexes it by
device offset, while the `Synth` object itself stays wherever its owner puts it. (An earlier reading
of these as `this + 0x288` and friends was wrong: `memset(&DAT_01327a20, 0, 0x400)` would have wiped
the voice array at `this + 0x480`, which the device plainly does not do.)

The fixture is already in place: `synth_render_fixtures` in `make_host_fixtures.py` keeps the object
in an allocation and the scratch in the library's `.bss`, stubs one engine render for all 132 voice
slots - the stub *fills* the engine's block from the increment, so the mixer has signal to scale -
and records 8 cases. `synth_render_fixture_is_alive` in `host.rs` checks it drives the real thing
until the port can replay it.

`Synth::render`'s signature is `(fract32_t *a, *b, *c, *d)`; the four blocks are the main output
plus the two FX returns and the sidechain the master compressor reads.

### What `Synth::render` does, in the order the C shows it

Measured from the decompilation (line numbers are the C's), with the **v1-reachable** path marked; the
input-signal, sampling, tone-mode and song-mode branches are gated on host flags the clone fixes at
zero, so they are documented rather than ported (the plan's `PORT_METHOD.md` rule).

1. **Setup** (1 500-1 700): `mutex_lock(this + 0x6864)`, `interpolateParameters`, then four master
   words at `+0x684c`/`+0x6850`/`+0x6854`/`+0x6858`, each folded one step toward a byte the song
   fixture carries (`master_params[0..4]`, the same 64th-order IIR `interpolateParameters` uses);
   `get_time_monotonic`; the module's two plug ids (`+0x60`, `+0x6c`) through
   `PlugManager::getPlugFlags`; `*(u64 *)(this + 0x6c40) = [0x7fffffff - *(u32*)(this+0x5d38),
   0x7fffffff - *(u32*)(this+0x5d80)]`.
2. **The track loop** (1 700-2 070), eight iterations, all reachable:
   * track 6 skips the LFOs and copies the FX/master parameter blocks (`+0x5c78`, `+0x5c80`, `+0x5c88`,
     `+0x5c90`, `+0x5c98`.., `+0x60f8`..) into the two modulation blocks and sets two words to
     `0x3fffffff`;
   * otherwise two `Lfo::render` calls - layer 1 at `+0x4ee4` with the block at `+0x5f48`, layer 0 at
     `+0x4d00` with `+0x5ac8` - with the modulation blocks as their `out` and `this + track*4 + 0x6ca4`
     (+`0x6c78`/`+0x6c4c` as the accelerometer inputs);
   * two `InstrumentManager::vibrato` calls (layer 0 from `+0x6c78`'s word, layer 1 from `+0x6c4c`'s);
   * `InstrumentManager::render(track, 0, mix, mod0, &counter)` and the same for layer 1 with `mod1`;
   * `trackFilterProcess` on `this + track*0x2c + 0x688c` and `trackFilterDcBlock` on
     `this + track*0x18 + 0x69ec`, both over the mix buffer and into the group sums;
   * the mix-down: each sample of the track mix is scaled by the track's gain (from `+0x50c8`,
     `+0x5148`, `+0x5108`, `+0x5188` and the two group gains `local_88`) with the `mul31` chains and
     saturating adds, accumulated into the group sums at `0x1227a20` (tracks 0-3) and `0x1227c20`
     (tracks 4-7), with per-track peaks at `this + track*2 + 0x6c10` and per-group peaks in the
     `local_a8` block (decayed by `* 0x7ed9 >> 15`).
3. **The master mix** (2 090-2 140): `param_1[i] = softclip(sat_add(group0[i], group1[i]))` where
   `softclip(x) = sat_add(x, sat_sub(x, mul31(mul31(x*x) * x)) >> 1)`. The C has a second, vectorised
   copy of the same arithmetic for the case where the output does not alias the sums.
4. **The FX sends/returns** (2 140-2 870): four `FxManager::render` calls with the plugs the manager
   has loaded. **v1 has none**, so each is a no-op, but the buffers around them (`0x12284a0`,
   `0x12288a0`, `this + 0xee8`..) and the `trackFilterProcess`/`trackFilterDcBlock` pairs after them
   still run.
5. **The master tail** (2 870-3 610): `param_1 += 0x12288a0`; `FxManager::render(0xb, this+0x5de0,
   param_1, ...)`; two more `trackFilterProcess`/`trackFilterDcBlock`; `bounceAudio`; the four
   `getBPM` reads and the `UNK_0017d064` table lookups that become `masterCompressor`'s four
   reference arguments; `masterCompressor(0x12288a0, ...)`; the master gain from
   `g_compressorLevel` and `this + 0x6854`/`0x6858`/`0x6264`/`0x6298`/`0x629c`; a soft limiter over
   the master buffer; the VU words; and the writes into the four caller buffers.

The two `(this + 0x6c10)`/`local_a8` peak paths and the four master words are pure bookkeeping: they
change no audio, but the fixture records them, so they must match too.

## The seam decisions a resuming session must not undo

* **`EngineVoice` (in `voice.rs`)** replaces the original's three per-voice function pointers
  (`+0x08` render, `+0x10` noteOn, `+0x18` noteOff). `InstrumentManager::render` should call
  `Voice::render_voice`, and the engine's state block at `+0x58`..`+0x16f` belongs to the engine.
  `SynthHost::reset_lfo` is the same kind of seam for the `g_synth` global that `Voice::noteOn`
  reaches.
* **Host values are arguments, never globals**: `VoiceHost { detune_index, auto_legato_glide,
  last_note }` (the sequencer's `centsDetune` index, `g_autoLegatoGlide`, `Voice::s_lastNote`).
  `masterCompressor` takes its whole state in `MasterCompressor`. `Lfo::render` takes `bpm`, `pitch`
  and `pitch_dz` in place of `Sequencer::getBPM` and the two accelerometer globals. Keep going that
  way: the chain owns one of each.
* **Embedded tables are generated**: `tools/gen-lfo-tables.py` and `tools/gen-voice-tables.py` read
  the `.so`; both have a `--check` mode. `Tuning::centsDetune` is the exception - it is `.bss` that
  `initTuning` computes, so `tuning.rs` computes it and the fixture checks all 2 401 words against the
  original's own output (the harness stubs `exp2`).
* **The ADSR types are still split**: `adsr::Adsr` (six words, the device's layout),
  `digital::DigitalAdsr` (four fields) and `sample_player_gain::Adsr`. The wired chain will need one
  of them as canonical, with adapters at the `EngineVoice::render` boundary - the engines update the
  level per frame, so the adapter must copy the four shared fields back.

## Fixture technique worth reusing

`make_host_fixtures.py`'s `voice_fixtures` writes Python stubs over the original's function pointers
(found with `opzso.stub_address`) and records the registers each stub was called with. That pins a
function whose callees are engines without pulling the engines in. Two traps already paid for:

* The three pointers are 8 bytes wide - write them with `write_u64`, and zero *both* halves of each
  slot in the recorded words or the stub address leaks into the comparison.
* Register arguments are easy to get backwards. `Voice::renderVoice` is `(this, out, params)`, and a
  fixture with `out` and `params` swapped silently pins the wrong thing - it cost two debugging
  rounds before the glide cases made sense. Check a call's argument order against the C *and* the
  disassembly before trusting a fixture that "fails oddly".

## Measured facts about the remaining pieces

* `Synth::render` is the global mixer. Its per-track work is: `Lfo::render` twice (or once) per layer,
  `InstrumentManager::render` twice (layers 0/1), `trackFilterProcess`, `trackFilterDcBlock`; then
  `masterCompressor` and `bounceAudio` over the master block.
* The mix buffers are library `.bss` scratch, 0x200 bytes apart: `0x12284a0`, `0x12286a0`,
  `0x12288a0`, plus `0x1228cec`/`0x1228d38` (small, and near the shared parameter block at
  `0x1228ca0`). The port must own them rather than reach for statics.
* `trackFilterProcess`'s tables are indexed `bank * 0x104 + row * 4` bytes - **0x104, not the 0x924
  between one table and the next**. Both indices read below the table (mode to -16, row to -64), so
  `filter_tables.rs` carries that padding.
* The filter's ramp flag does not only enable a pass: it *replaces* the value the state's cutoff word
  ramps toward with `(0x1fffffff - cutoff)` (zeroed when negative) `<< 2`, before anything else reads
  the parameter. The row weight still uses the original `(cutoff & 0x1ffffff) << 6`.
* `Synth::resetLfo(this, track, layer, params)` resets the LFO at
  `this + track*0x2c + layer*0x1e4 + 0x4d00` with the parameter block at
  `this + track*0x48 + layer*0x480 + 0x5ac8`, and repeats the first one when `layer == 1` and
  `[g_sequencer + 0x1c] == 0`. The LFO array's layer stride is *eleven* slots, so slot 11 is both
  track 11 of layer 0 and track 0 of layer 1.
* One `Lfo` is 0x28 bytes of state inside a 0x2c-byte slot: `+0x07` and `+0x1e`..`+0x1f` are bytes no
  LFO path touches, and a byte-exact port carries them anyway.
* The random value comes from one library-wide LCG (`randSeed`, shared with `AnalogA`'s noise), so
  `Lfo` takes `&mut seed` rather than owning one. The chain must own exactly one and hand it to both.
* `Synth` is at least 0x6d2f bytes (the mute byte at `+0x6d2e`); the harness allocates 0x7000.
* `InstrumentManager` owns 44 voices at a 0x190 stride; `Voice::s_lastNote` (16 bytes) is at
  `0x16e8b48`, `g_autoLegatoGlide` at `0x1de770`, `g_synth` at `0x1227798`,
  `Tuning::centsDetune` at `0x1228d88` (2 401 words), `g_bouncingAudio` at `0x12322a0`,
  `bounceWritePos` at `0x1232298` and `bounceBuffer` at `0x122de98`.
* `tools/resolve-got.py <slot>...` resolves a GOT slot to its symbol and address from
  `.rela.dyn`/`.rela.plt` - that is how the globals above were found (`python3 tools/resolve-got.py
  0x1d58f0`).
